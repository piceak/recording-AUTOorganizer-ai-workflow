# note-digest · 讲稿解读（第二步）

第 2 步：基于**已标注**的讲稿做笔记。第 1 步由 `note-annotate`（标黑/标灰/纠错/补已标记）完成。本命令假定讲稿已完成标注（文末有 `<!-- 已标记 -->` 且 state=1）。

## 两类文件（务必分清）

- **讲稿文件（原文 + 标注）**：课程文件夹内同名 `.md`。内容：① 原文讲稿（含 `##` 标黑 / `#` 大标题 / 灰色 span / 行内 `[?]`）；② 文末 `<!-- 已标记 -->` 游标。
- **笔记文件**：同文件夹内 `原文件夹名+笔记.md`。存放全部解读笔记；不存在则创建。**本 skill 只写笔记文件。**

## 判断要不要做

```bash
python _system/check_state.py --file "<讲稿文件>"
```

返回的 `action`：
- `digest` → 已标记未解读，**本次任务**。
- `mark` → 尚未标注，先走 note-annotate，结束。
- `done` → 已解读且已笔记，结束。
- `empty` → 没写原稿，结束。

> 若遇到 `mark`，直接说明"需先标注"，不要动手；`done`/`empty` 直接结束。

## 用户指令

用户说"解读示例课程"→ 定位同名 `.md`（讲稿）+ `同名+笔记.md`（笔记）。
用户说"全部解读"→ 逐个处理。
用户说"扫描/解读"时有 `digest` → **直接做完，不用中途停下等确认**。

## 步骤

### 1. 检测

```bash
python _system/check_state.py --file "<讲稿文件>"
```
确认 `action=digest` 才继续。

### 2. 解读与写笔记（一次完成）

- **解读**：读讲稿文件全文，**优先依据标黑（`##`）与大标题（`#`）部分**抓重点；标灰部分作为"非重点"处理，可不纳入笔记；行内 `[?]{正确词}` 收集进「存疑待查」。
- **判重点的又一准则**：某个点在讲稿里**出现频率高**，或**占据篇幅大**（老师反复展开、讲得多、花了大量时间），也同样列为重点纳入笔记——不限于是否带"重点/考点"字样。体现在笔记里：核心概念表、要点整理里都应突出这类高频/大篇幅的点。
- 对照笔记文件既有的笔记区块（看日期与覆盖内容）：
  - 有真正的新讲稿 → 正常解读，写全六节模板；
  - 变化只是编辑/清理/对账 → 精简区块（一句话概括 + 要点整理说明现状）；
  - 讲稿被截断/损坏 → 在「存疑待查」标 `[?]`。
- **写笔记**：把解读结果**一次写入**笔记文件（`<课程>笔记.md`）的「📒 解读笔记」区块——解读和笔记在同一轮完成。**不改原稿。**

### 3. 写笔记文件

**笔记 → 笔记文件末尾**（旧笔记一律保留），标题 `## 📒 解读笔记（YYYY-MM-DD HH:MM）`：

```
## 📒 解读笔记（YYYY-MM-DD HH:MM）

### 一句话概括
### 核心概念
| 术语 | 解释 |
|---|---|
### 要点整理
### 易混·易错
### 自测
### 存疑待查
```

质量：术语给规范名+白话解释（写成规范的表格行）；明显听写错误按 `[?]` 里的正确词修正并在存疑待查注明 `[?]`；宁缺毋滥；基于标黑重点，不编造原文没有的内容。**存疑待查**汇总原稿里所有 `## 存疑待查` 区块的 `[?]` 条目（原稿已由 note-annotate 打标，此处只汇总到笔记，不在原稿重复标记）。

### 4. 设状态 + 确认

```bash
python _system/verify_digest.py "<讲稿文件>"    # 强约束校验
python _system/check_state.py --file "<讲稿文件>" --set-state 2
```

- `verify_digest.py`：校验"存疑待查条目数 ≤ 原文 `[?]{...}` 打标数"。必须输出 `{"done": true}` 才继续；若 `done` 为 false，说明有存疑条目漏打在原文，**先回 note-annotate 补标**，不要设 state=2。
- `--set-state 2`：记录"已解读并已笔记"，下次 `check_state.py` 会输出 `done`。
- 完成后极简确认：笔记已写入笔记文件、状态已置 2。本 skill 不改讲稿原文。

## 与 note-annotate 的关系

本 skill 是第 2 步。`note-annotate`（第 1 步）负责标黑/标灰/打 `[?]`/补 `<!-- 已标记 -->`，并设 state=1。本 skill 只读讲稿、只写笔记、设 state=2。两者通过 state.json 联动，把"未标注↔待解读↔已完成"区分开。
