# note-annotate · 讲稿标注（第一步）

只做**标注**，不写笔记、不改原文实质词句。目标是给未标记的新讲稿段加上"重点分层"，并同步文末「已标记」游标，供后续 `note-digest` 基于标黑/标灰内容做笔记。

> **首要原则：先结合课程名与讲稿内容做判断。** 标注前，先根据**课程名称**（这门课讲什么、考核方向是什么）与本节内容（这段在讲什么、是否相关、是否值得记）对照起来判断：什么算重要、什么算无关。课程名给出课程主线与考核口径，内容是具体讲稿，两者结合才能准确划分哪些该标黑、哪些该标灰。不要脱离课程大类孤立看一段文字。

## 目标文件

课程文件夹内与文件夹同名的讲稿文件（如 `示例课程/示例课程.md`）。用户说"标注一下示例课程"→ 定位该文件夹的同名 `.md`。

## 检测（先判断要不要做）

先跑检测，只处理「有未标记新内容」的文件：

```bash
python _system/check_state.py --file "<讲稿文件>"
```

返回 JSON 的 `action` 字段：
- `mark` → 有未标记段，**本次任务**。会给你 `unmarked_text`（未标记段，逐字 verbatim，供 Edit 精确匹配）+ `context_heading`（上方最近的章节标题）+ 课程名。
- `digest` / `done` / `empty` → 不需要标注，结束。`digest` 表示已标记待解读（归 note-digest），`done` 表示全部完成，`empty` 表示没写原稿。

> 若 `action != mark`，直接停止并说明当前状态，不要动手。

## 标注规则（分层）

对 `unmarked_text` 里的内容做三类处理（两类标记 + 行内纠错）：

- **标黑（重要，`##` 二级标题）**：
  - 老师的**考试重点、核心概念、定理、公式、结论**；
  - 需要记住的关键术语、因果关系、易考点；
  - 一段话的**主旨句**。
  - 写法：把该句提升为 `## <该句/该节要点>`。一段重要内容可单独设一个小标题，标题概括其要点。
  - 一本书/一节内容，标黑不要过多（重点突出即可，宁精勿滥）。

- **大标题（`#`，跟考试相关的区段）**：
  - 仅当满足"这与考试挂钩的大区段"时使用，把这一大节（如一章、一个大知识点群）提为 `# 标题`。
  - 用于**层级更高**的划分，供后续笔记按大标题聚合；不要滥用，一节内容里 `#` 至多一两处。

- **标灰（不重要，灰色 span）**：
  - 老师闲聊、签到、点名、休息、与课程无关的口水话；
  - 重复啰嗦、口语语气词（"对吧""大家看一下""对不对"）等无信息量的内容；
  - **整段明确无价值、不考试的**内容才包灰。
  - 写法：把该段包在 `<span style="color:gray">` 与 `</span>` 之间（Obsidian 原生支持 HTML）。
  - 注意：在重点段落里零散的口语词不逐个标灰（会破坏语义），靠标黑突出主体即可。

- **行内纠错 `[?]{正确词}`（听写错误/截断）**：
  - 讲稿里老师口述有明显听写错误、或话没说完就被截断的地方，在错误/截断处打 `[?]`，紧跟上 `{你认为正确的词汇}`。若完全无法判断原意，只打 `[?]`。
  - 只有标注模型改原稿，所以**只有本 skill 负责打 `[?]`**；`note-digest` 只读原稿、在笔记文件汇总。
  - **每条存疑都必须落到原文对应位置**（`[?]{正确词}`），否则 `verify_digest.py` 强约束不通过、任务会被判重做。

## 存疑待查（随「已标记」游标多次出现）

- 每一轮标注完成后，把**本轮打下的 `[?]` 条目**写在**一个 `## 存疑待查` 区块**里，放在**对应的 `<!-- 已标记 -->` 之前**。
- 旧轮次的存疑待查区块保留不动（历史轮次），只在本轮新增一个新区块，格式：
  ```
  ## 存疑待查
  - `面向对象基础[?]`：疑为上一节残留内容，正文未展开
  <!-- 已标记 -->
  ```
- 区块内容 = 本轮新增的 `[?]` 条目汇总（含原文那句 + 你的判断）。这些条目必须是你在原文用 `[?]{正确词}` 打标过的。
- `check_state.py` 与 `verify_digest.py` 都能识别与排除这类区块：它们位于已标记游标之前，会被当成"已处理内容"；校验时只比对"存疑区块里的 `[?]` 条目数 ≤ 原文打标数"。

## 步骤

1. **检测**：`python _system/check_state.py --file "<讲稿文件>"`，拿到 `action="mark"` 时的 `unmarked_text`、`context_heading`、课程名。
2. **标注**：只针对 `unmarked_text` 这段做标注：
   - 结合 `context_heading`（上方最近的章节标题）与课程名判断这段属于哪一大节，标黑标题沿用该节主线，宁精勿滥；
   - 重要 → 提为 `## 要点标题`（或在该句前加 `##`）；
   - 需考试大区段 → 提为 `# 大标题`；
   - 不重要 → 包灰色 span；
   - 听写错误/截断 → 打 `[?]{正确词}`。
3. **写回**：用 `Edit` 把 `unmarked_text` 整段替换成标注后的文本。`old_string` = 脚本给的 `unmarked_text`（原样，逐字），`new_string` = 标注后文本 + 一个空行 + `## 存疑待查` 区块（本轮 `[?]` 条目）+ 一个空行 + `<!-- 已标记 -->`。只增删标注标记，**不改动原文实质性词句**（除 `[?]` 纠错处）。
4. **强约束校验**：`python _system/verify_digest.py "<讲稿文件>"`，必须输出 `{"done": true}` 才通过；若 `done` 为 false（存疑条目数 > 原文打标数），按 `fails` 补做（把漏打的 `[?]{...}` 补到原文对应位置）再重跑。
5. **设状态**：`python _system/check_state.py --file "<讲稿文件>" --set-state 1`（记录"已标注未笔记"）。
6. 结束，**不写笔记文件**。

> 只改讲稿文件本身。`## 存疑待查` 区块必须放在对应的 `<!-- 已标记 -->` **之前**；`<!-- 已标记 -->` 成为文件末尾。若文件原本末尾还有其它内容，把本轮存疑待查 + 已标记加在该段之后即可。旧轮次的存疑待查区块保留，勿删。

## 与 note-digest 的关系

本 skill 是第 1 步；`note-digest` 是第 2 步（基于标注写笔记、在笔记文件汇总存疑待查）。不要在本 skill 里写笔记、不要设置 state=2（那是解读完成后的事）。

## 不作改动

- 不写/不改笔记文件；
- 不改原文实质性词句（只加标注；`[?]` 例外）；
- 不设置 state=2；
- 不在未标记段之外（即文件已有内容里）添加任何东西。
